# Клиент Windows: оформление Newservice, движок Raw

Новый интерфейс находится в ui/newservice. Темы, оформление боковой панели и расположение экрана подключения перенесены из предоставленного пользователем проекта Newservice / FTDirect. Его движок WireGuard не используется; backend запускает отдельный raw-client.exe. Лицензия исходного UI сохранена в ui/newservice/LICENSE.

Готовый личный комплект с профилями, треем, таймером и исправленным служебным DNS: dist/windows-ui-appdata-ready. Он содержит profiles.json с отдельной конфигурацией каждого сервера и ключами в текстовом виде. Эти данные не входят в Git и публичный комплект. Распакуйте весь ZIP перед запуском. Нужен Windows x64 и WebView2 Runtime (обычно установлен в Windows 10/11).

1. Закройте прежнее окно fturn Raw. При активном Raw сначала отключите его кнопкой. Системный VPN отключать не нужно.
2. Откройте FturnRaw.exe и подтвердите стандартный запрос Windows на права администратора для Wintun и маршрутов.
3. Нажмите большую кнопку подключения. Личный профиль уже заполнен: TCP к VK TURN, MTU 1420, 10 потоков, весь IPv4 через Raw.
4. При включённом «Сворачивать в трей» закрытие и сворачивание окна скрывают интерфейс, сохраняя соединение. Отключение Raw выполняется кнопкой питания; полный выход — через меню трея или настройки приложения. При выключенной настройке закрытие окна отключает Raw и восстанавливает сетевые настройки. При аварийном завершении очистку выполняет отдельный защитный процесс.

Внешний адаптер выбирается перед подключением по текущему системному IPv4-маршруту. При включённом системном VPN клиент использует его. Если VPN выключен, выбирается действующий Ethernet/Wi-Fi. Клиент не переключается автоматически на физический адаптер при ошибке VPN. Сам системный VPN не отключается.

Маршруты добавляются после первого подтверждённого Raw-соединения. Существующие маршруты другой VPN не удаляются; локальные и служебные более точные маршруты сохраняются. В полном режиме исходящий IPv6 блокируется временным правилом Windows Firewall. DNS вне адреса адаптера Raw блокируется для UDP/TCP 53 и 853; DNS Windows направляется через NRPT на 1.1.1.1 и 9.9.9.9 с отдельными маршрутами через Raw. Правила записываются в журнал состояния до изменения системы и удаляются при отключении, ошибке, аварийном закрытии или следующем запуске. Защитный процесс запускается до изменения сети. Отдельного общего IPv4 kill switch нет. До готовности Raw используется прежнее соединение; в режиме «Только соединение с сервером» защита не применяется. Служебный DNS только процесса raw-client идёт по HTTPS к Cloudflare через выбранный внешний адаптер. Это позволяет заново получить адреса VK/TURN даже при обрыве всех потоков Raw; открытого DNS на внешний адаптер он не отправляет. DNS Windows и остальных приложений остаётся в туннеле. Браузерный DoH не перенастраивается; его HTTPS-трафик следует IPv4-маршрутам.

Нажатие на выбранный сервер открывает список профилей над строкой выбора. У каждого сервера есть шестерёнка редактора и кнопка удаления с подтверждением; кнопка «+» сверху создаёт новый профиль. В боковой панели остаются подключение, журнал, тема и настройки приложения. Для смены профиля нужно отключить Raw. Удаление выбранного профиля переключает на оставшийся; последний профиль не удаляется. Выбор сохраняется после перезапуска. Старый connection.json автоматически читается при отсутствии profiles.json; его ключ из файла переносится в текстовое поле. Старые файлы остаются для восстановления. После первого изменения список атомарно сохраняется в profiles.json.

В начале редактора профиля есть поле «Вставить ссылку конфигурации» и кнопка «Добавить профиль из ссылки». Парсер принимает `fturnraw://` с JSON v1 в base64url. Ссылка содержит сервер, VK-звонок, сам ключ, MTU, потоки и режим трафика; TCP фиксирован. Импорт проверяет всю конфигурацию до записи и добавляет новый профиль, сохраняя предыдущие. Повторный импорт одинаковой конфигурации выбирает существующую запись. Ошибочная ссылка не меняет список. Во время работы Raw добавление и импорт сохраняют новый профиль в списке, сохраняя текущий активный сервер и соединение. Повторный импорт уже сохранённого профиля не переключает подключение. Раздел «Создать ссылку из этих настроек» создаёт и копирует переносимую ссылку. Ссылка и profiles.json содержат ключ доступа: передавайте их только тому, кому разрешаете подключаться. Ссылки обычного FreeTurn/WireGuard имеют другой формат и этой версией не импортируются.

Настройки: название профиля, IPv4:порт сервера, ссылка VK-звонка, Raw key (64 шестнадцатеричных символа), MTU, число потоков и режим трафика. Отдельный файл ключа больше не нужен. Движок получает ключ через существующий аргумент -obf-key; SSH-ключи приложение не использует. Ключи и ссылки звонков сохранённых профилей скрываются в журнале. Вторая опция трафика создаёт только соединение с сервером без общего перенаправления интернета. Журнал доступен на боковой панели и записывается в ui.log рядом с приложением.

Сборка: scripts/build-raw-ui.ps1. Требуются Go, Node/npm и Wails v2.13.0. Скрипт создаёт публичный комплект без ключа и личной ссылки. Исходные зависимости Newservice обновлены в пределах разрешённых версий; npm audit сообщает 0 уязвимостей.

## Исправление периодических потерь

Применено на клиенте и сервере. Каждый поток имеет постоянный логический идентификатор, но при каждом handshake получает свежие криптографические nonce и ключи. Сервер заменяет прежнее направление только после подтверждения нового. Уведомление через рабочий поток удаляет точно указанную старую сессию; позднее уведомление не удаляет её замену.

TURN ChannelBind обновляется через 110–130 секунд, allocation — через 225–255 секунд, максимум половину начального срока allocation. Периоды распределены между потоками. В журнале видны сроки allocation, запросы и результаты Refresh/ChannelBind. Отклонённый Refresh теперь возвращает ошибку и приводит к восстановлению направления.

Подтверждены локальные тесты принудительного TCP-сброса и доставки после восстановления, свежие ключи, защита от позднего уведомления, замена при 64 потоках, сохранение настроек UI и сборки Windows/Linux. Предпросмотр UI проверен в обеих темах. Длительный тест VK не завершён: TCP TURN недоступен через текущий системный VPN; отдельный тест с VPS остановлен перед ручной проверкой пользователя после таймаутов VK/CAPTCHA. Отсутствие пятиминутных потерь в реальной игре пока не подтверждено.

Проверки защиты: `scripts/test-raw-routes.ps1` изолированно проверяет IPv6/UDP/TCP-фильтры, удаление правил при исчезнувшем TUN, откат частичной установки и сохранение правил другой VPN. Реальное добавление тестового правила из текущего процесса Windows требует повышения прав; клиент содержит манифест requireAdministrator. Живую проверку BrowserLeaks пользователь выполняет после запуска новой сборки с UAC. Если брандмауэр отключён или другая программа задала catch-all NRPT, полный режим завершается с ошибкой и откатывает свои изменения.

Справка по используемым Windows API: [New-NetFirewallRule](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule), [Add-DnsClientNrptRule](https://learn.microsoft.com/en-us/powershell/module/dnsclient/add-dnsclientnrptrule).

Служебный DoH реализован по [RFC 8484](https://www.rfc-editor.org/rfc/rfc8484.html) и [документации Cloudflare](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/). HTTPS использует проверку сертификата, фиксированные IPv4-адреса и тот же внешний адаптер; системный прокси и редиректы не применяются.

Дополнительно подтверждено: опциональный `TestControlDNSLiveUnderlay` разрешил vk.ru через HTTPS по текущему включённому системному VPN (интерфейс 47). Маршруты и DNS Windows при проверке не менялись. Общий `go test ./...`, backend UI и изолированные проверки защиты прошли.


Исправление Windows Firewall: на этой Windows префикс `::/0` отвергается с HRESULT 0x80070057. IPv6-правило использует две подсети `::/1` и `8000::/1`, вместе покрывающие всё IPv6. `scripts/test-raw-firewall-live.ps1` запускается с правами администратора и проверяет настоящие фильтры только в выключенных правилах, затем удаляет их. Проверка воспроизвела ошибку старого префикса и подтвердила принятие нового IPv6-фильтра и обоих DNS-фильтров; оставшихся тестовых правил — 0. Это подтверждает совместимость адресных фильтров с Windows Firewall, но не заменяет проверку полного подключения и BrowserLeaks.


Исправление служебного DNS после включения защиты: запуск Raw-сессии раньше повторно вызывал общий DNS-режим auto и заменял специализированный HTTPS-резолвер режимом UDP, выбранным до установки брандмауэра. Теперь исходящие HTTP-запросы провайдера VK и общие DNS-запросы TURN получают один выделенный резолвер. В журнале выводится `[DNS] Raw service DNS: HTTPS via selected underlay; UDP/53 disabled for VK/TURN lookups`. Служебные сокеты привязаны к текущему внешнему адаптеру через IP_UNICAST_IF; DNS приложений остаётся под политикой Raw.

`scripts/test-raw-control-dns-live.ps1` создаёт временные блокировки UDP/TCP 53 и 853 только для отдельной тестовой программы, запускает инициализацию DNS Raw-сессии и шесть живых разрешений vk.ru/login.vk.ru через внешний адаптер, затем удаляет собственные правила. Проверка на Ethernet 5 прошла за 3.65 секунды; оставшихся тестовых правил — 0. Полный go test ./... и go vet для изменённых пакетов прошли. Готовый личный комплект с исправленным ядром: dist/windows-ui-profiles-dns-ready.


## Трей, время соединения и настройки приложения

Таймер HH:MM:SS считается в backend по монотонному времени после подтверждения Raw-соединения и применения маршрутов. Время первоначального подключения не учитывается. Потеря всех потоков приостанавливает таймер; восстановление продолжает его. Новое подключение, отключение или ошибка сбрасывают время. При скрытом окне отсчёт продолжается; подсказка значка в трее показывает состояние и время.

Левый щелчок или двойной щелчок по значку показывает окно. Правый щелчок открывает пункты «Открыть fturn Raw», «Подключить/Отключить», «Выход». Выход вызывает существующий механизм отключения и очистки собственных сетевых правил. Если трей не инициализировался, окно не скрывается.

Настройки приложения отделены от параметров профиля и хранятся в %LOCALAPPDATA%\fturn-raw\app-settings.json. По умолчанию сворачивание в трей включено, запуск с Windows и авто-подключение выключены. Настройка трея управляет поведением окна; значок остаётся доступен, пока приложение запущено. Авто-подключение использует выбранный профиль при каждом запуске. Автозапуск создаёт собственную задачу Планировщика Windows для текущего пользователя, с интерактивным входом и повышенными правами, нужными Wintun. Отключение удаляет только эту задачу. Если автозапуск включён, запуск новой версии обновляет путь собственной задачи на текущий EXE. Задачи прежних версий удаляются только при подтверждённой принадлежности этому приложению и пользователю.

Задача автозапуска создаётся только после включения переключателя пользователем. После установки автозапуска или его удаления настройки записываются атомарно; ошибка записи вызывает обратное изменение задачи. Повреждённый файл настроек остаётся нетронутым. Для экспериментального Raw нет канала обновлений: настройки не устанавливают обычное FreeTurn/WireGuard-ядро из референса.

Backend разделён на управление соединением, проверку профиля, учёт активного времени, хранение настроек, управление автозапуском, политику окна и адаптер системного трея. Политика окна зависит от узких интерфейсов WindowHost/TrayDriver, хранилище настроек — от StartupManager. React разделён на компоненты главного экрана, меню серверов, редактора профиля, настроек приложения, журнала и hook получения состояния. Параметры подключения и wire-формат fturnraw://v1 не изменены.

Проверки: backend Go tests для паузы/возобновления таймера, закрытия/сворачивания/выхода и отсутствия трея, отката автозапуска при ошибке записи, сохранения повреждённых настроек и предыдущие проверки профилей/ссылок; отдельный опциональный TestNativeTraySmoke создаёт и удаляет настоящий значок Windows без запуска VPN. Регрессии scripts/test-raw-routes.ps1 проверяют прежнюю защиту DNS/IPv6 и сохранение системного VPN. Код автозапуска использует [New-ScheduledTaskPrincipal](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtaskprincipal) и [New-ScheduledTaskTrigger](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasktrigger).

Добавление через «+» доступно при активном подключении. Смена сервера и изменение активного профиля требуют отключения Raw. Таймер уменьшен до 12 px; используется обычная кнопка сворачивания в заголовке Windows.


## Постоянные данные в LocalAppData

Профили, выбранный сервер и настройки приложения сохраняются в одной папке текущего пользователя: `%LOCALAPPDATA%\fturn-raw`. В ней находятся `profiles.json`, `app-settings.json` и `ui.log`. Точный путь показан в настройках приложения. Папка определяется через Windows Known Folder API, без привязки к имени пользователя или расположению EXE.

При отсутствии profiles.json в AppData выполняется однократная миграция profiles.json из папки приложения; если такого файла нет, проверяется старый connection.json. Ключи из локальных файлов переносятся в текстовое поле профиля, поэтому сохранённое подключение не зависит от прежней папки. Имена, параметры и выбранный профиль сохраняются. app-settings.json переносится отдельно при отсутствии соответствующего файла в AppData. Исходные файлы остаются для восстановления.

Файлы публикуются атомарно, без замены уже существующего назначения. При последующих запусках данные AppData имеют приоритет над комплектом из папки новой сборки. Повреждённые профили не заменяются старой копией; при недоступности AppData приложение сообщает ошибку и не переключает сохранение обратно в папку EXE. Другие папки клиентов в AppData не затрагиваются.

Ядро, DLL и routes.ps1 по-прежнему загружаются из папки EXE. route-state.json и работа защитного процесса остаются в прежнем месте. Формат профиля и ссылки подключения не изменён. Дополнительные тесты проверяют миграцию двух профилей и настроек, независимость от старого файла ключа, доступ из другой папки EXE, сохранение существующих/повреждённых данных и ошибки доступа. Реальную миграцию можно выполнить тестом TestInstalledUserDataMigration с переменной FTURN_UI_MIGRATE_SOURCE, указывающей прежнюю папку приложения; он не запускает Raw и не меняет маршруты.

Используется [SHGetKnownFolderPath](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetknownfolderpath) с FOLDERID_LocalAppData.
