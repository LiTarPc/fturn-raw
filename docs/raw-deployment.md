# Установка Raw на Debian и запуск клиента Windows

На проверенном VPS установлен отдельный `fturn-raw.service`: UDP 56010,
интерфейс ftraw0, сервер 10.77.0.1/24, клиент 10.77.0.2/24, MTU 1420.
Существующие службы fturn не заменяются. Этот эксперимент обслуживает один
IPv4-адрес клиента на выделенный ключ; параллельный запуск второго клиента
с тем же ключом вытеснит первый.

## Файлы на VPS

- `/opt/fturn-raw/raw-server` — сервер.
- `/opt/fturn-raw/raw-firewall` — добавление/удаление только собственных правил.
- `/etc/fturn-raw/raw.key` — новый ключ, права 0600.
- `/etc/systemd/system/fturn-raw.service` — автозапуск сервера.

Команды управления:

```bash
systemctl status fturn-raw --no-pager
journalctl -u fturn-raw -n 30 --no-pager
systemctl restart fturn-raw
# Остановить эксперимент и снять его правила firewall/NAT:
systemctl disable --now fturn-raw
```

Правила помечены `fturn-raw-experiment`, ограничивают forwarding/NAT адресом
10.77.0.2/32 и снимаются через ExecStopPost. IP forwarding на VPS уже был включён;
скрипты это проверяют, но не меняют глобальное значение. Они рассчитаны на
проверенный внешний интерфейс `ens3`, порт 56010 и подсеть 10.77.0.0/24.
Для другого VPS сначала поменяйте эти значения и проверьте конфликты.
После перезагрузки правила ставит systemd-служба. После ручного `ufw reload`
выполните `systemctl restart fturn-raw`, чтобы восстановить её собственные правила.

Установочные файлы находятся в `scripts/debian`. `install-staged.sh` запускается
из каталога с Linux x64 `raw-server`, `raw-firewall.sh`, `fturn-raw.service`;
при существующем ключе/службе он отказывается перезаписывать установку.

## Клиент Windows

Личная готовая конфигурация лежит в `dist/deployment-windows`. В неё входят
raw-client.exe, официальный wintun.dll, raw.key, Start-Raw.ps1, Stop-Raw.ps1.
Скрипт запуска уже содержит адрес сервера и предоставленную VK-ссылку.
Этот каталог содержит закрытый ключ: не публикуйте его и не включайте в общую
сборку. Публичный ZIP Windows не содержит ключа или личной VK-ссылки.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Raw.ps1
# Подтвердите UAC, если Windows запросит права администратора.
Get-Content .\client-status.json
Get-Content .\client.stderr.log -Tail 20
# Остановка клиента:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Stop-Raw.ps1
```

Start-Raw.ps1 запускает клиент в фоне, проверяет ping сервера и временно
направляет 1.1.1.1/32 через TUN для проверки интернета. Потом этот тестовый
маршрут удаляется; клиент продолжает работать. Статус `verified` означает,
что обе проверки прошли. Маршрут по умолчанию не меняется: весь трафик Windows
автоматически в Raw не переключается. Для первого ручного теста достаточно
`ping 10.77.0.1`. Как добавить и убрать маршрут отдельного адреса, описано
в `docs/raw-experiment.md`.

В списке адаптеров ftraw0 может иметь описание `WireGuard Tunnel`: это имя
обёртки Wintun из используемой Go-библиотеки. Движок и шифрование WireGuard
в Raw не запускаются; IP-пакеты защищает собственный RTP/AEAD транспорт.

## Реальная проверка

Подтверждены Linux TUN, Windows Wintun, авторизация VK, три TURN TCP-потока,
шифрованная передача IPv4 и интернет через NAT VPS. Первый короткий замер:
4.81 Мбит/с скачивание и 0.85 Мбит/с отправка одним внутренним TCP-потоком.
Это измерение одной конфигурации, без сравнения с WG. Полный VPN, IPv6 и
стабильное преимущество по скорости ещё не проверены. Подробности и условия
замера находятся в `docs/raw-validation.md`.
Обновление MTU: установлен 1420 на сервере и в Start-Raw.ps1. Программа теперь
поддерживает до 1500 за счёт разбиения крупных IP-пакетов внутри Raw. Сеть VPS
наружу имеет path MTU 1472, поэтому для этой установки оставлен 1420.
Test-BrowserLeaks.ps1 проверяет fingerprint отдельным curl-запросом через Raw
и убирает временный маршрут к сайту. HTML и JSON результата находятся рядом
с клиентом; curl был запущен без прокси с исходным адресом 10.77.0.2.
Обычный браузер автоматически в Raw не переключается.
